## Handoffs and evidence

- `/root/visual_analysis` inspected the live site at 1280 × 720 and produced `/tmp/mnh-reference/hero.png`, `content.png`, `articles.png`, `about.png`, and `footer.png`. Observed: 54px header; 48/48px centered hero; 40px page gutters; five portfolio cards, two editorial cards, black company statement and illustrated contact section.
- `/root/product_design` inspected library integration and identified registry, page-shell, catalog, route and source-panel requirements. No implementation files assigned.
- `/root/art_direction` inspected actual source imagery and font URLs and supplied source image paths in `/tmp/mnh-art/`. Direction: monochrome institutional typography, hairline rules, retro-futurist imagery and a black statement panel. No implementation files assigned.
- `/root` implemented `pilot/src/mnh.jsx`, `mnh.css`, `mnh-tokens.css`, `mnh-data.js` and integration in the existing registry, catalog, page shell, router and specimen styles. Page and section captures are under `pilot/public/previews/mnh/`; full rendered desktop/mobile captures and the comparison image are in `pilot/public/evidence/mnh/`.
- `/root/independent_qa` inspected source and current output captures, working routes, keyboard behavior and responsive widths. Initial findings: mobile menu lacked an accessible name, Escape did not dismiss the menu, system specimen used the wrong typography/surface, mobile selection retained a desktop comparison, and viewport overflow occurred at 701–1024px. The implementation owner corrected each and re-rendered. Independent QA rechecked and **passed** the delivered revision for the inspected scope. Document width matched viewports at 320, 375, 390, 700, 701, 768, 900, 1024, 1099, 1100, 1101, 1120, 1150, 1200, 1280 and 1440px. All six thumbnails and source/page/system routes loaded; Enter and Escape worked for the menu. A final focused recheck also confirmed the hero link’s visible keyboard focus indicator after a CSS correction. The review does not assert pixel identity or end-to-end service behavior.

## Limits and validation

Source capture shows TWK Lausanne and publicly served source images. The date is fixed to the captured date; the menu is an accessible implementation adaptation; portfolio and editorial links lead to source destinations. Desktop first viewport is measured and paired for comparison; lower sections and mobile remain approximations, especially spacing and card geometry. No backend or other MNH pages were recreated. Local retained assets are for this private design study.

A Vite production compilation passed with `publicDir: false`, which validates transformed application code but does not validate copying the existing public tree. The standard build stalled while reading an existing `public/blueprint-source/landing/tools/ascii-logo.png` file; the existing `npm run check` also stalled while reading its script in this environment. Both were stopped. Browser checks confirmed the new local assets and routes loaded.
