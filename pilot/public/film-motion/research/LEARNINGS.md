## Story, argument, and proof

| Learning | Evidence / foundation | Skill decision |
|---|---|---|
| Let actual product behavior perform the plot | B16 Linear f81–1325; B14 AutoRouter f216–830 | Carry one case from context through action to changed result. Avoid a parade of unrelated hero screens. |
| Explain a mechanism before a metric or offer | A04 Runinfra mechanism→case→offer; B03 Ramp disorder→organized process | Map every claim to visible evidence. Reference metrics remain source claims, not reusable facts. |
| Show a human consequence beyond a capability | A07 Perplexity's delegated tasks and connected people | Connect a goal, work performed, and what the person can now do; preserve downstream state. |
| A metaphor can become a whole argument | Memorable maze→stored paths→recall graph→identity | Choose a motif whose changing relationship explains the product, rather than repeating a decorative symbol. |
| Classify references by what they actually are | A02/A06/B02/B04/B08 multi-panel studies; B06 process; B09 prototype | Borrow choreography from a loop, art direction from unused shots, and structure from whole films. Do not infer a linear plot from simultaneous panels. |
| Select duration from audience, goal, placement and evidence | User clarification plus authored story synthesis | Recommend a working runtime; time the natural read and proof. Cut or restructure beats before speeding them up. Honor an explicit runtime. |
| VSL needs an accumulating argument | Story research and production synthesis | Explain the mechanism, establish credible proof, address material objections, then make an accurate offer/action. Do not stretch a brand montage into a long sales film. |

## Art direction, editorial design, and palette

| Learning | Evidence | Skill decision |
|---|---|---|
| One material world can supply variety through scale/light | A01 Leap's ribbed metallic world, followed by product color | Define geometry/material/light before separate shots; reserve a palette break for a meaningful reveal. |
| A brand primitive can become layout, mask and pattern | B10 Outset Law f220–1615 | Define proportions, spacing and transformation rules, then reuse the module in multiple editorial roles. |
| Applications demonstrate a flexible identity | B07 Bitstack f531–750; B10 applications | Typography, physical objects, UI and photography should share a recognizable grammar. |
| Give colors semantic jobs | B05 AutoBot; B04 EthenaPay confirmations; B03 lime operations | Assign stage, ink, actor, operation, state and completion roles. Avoid choosing each scene's palette independently. |
| Backgrounds can have their own slower rhythm | B13 Elio variants; A13 iamcfw study | Protect foreground legibility while the ground changes shape/hue; plan adjacent shot relationships. |
| Editorial interest can come from information itself | B12 Tensorlake; Skale TypeSafe/Baseten excerpts | Use scale, columns, copy, code, alignment and deliberate holds. Do not add a camera move merely to animate a static layout. |
| Type impact needs a readable destination | B07 f0–84; B03 f732–794 | Cropped/fast/warped type can introduce emphasis, then resolve into a complete stable phrase. |
| Human sets and UI can share art direction | A07 Perplexity; Skale Cognition/Baseten excerpts | Reserve a reading zone, constrain props/materials, and carry color/shape across footage and graphics. |

## Motion, transformations, and cinematography

| Learning | Evidence | Skill decision |
|---|---|---|
| A retained anchor makes complex change traceable | B01 primitive→symbol→UI; A05 mobile/context handoffs | Name what survives the join and independently time container, content, copy, cursor and camera. |
| Semantic reveal order can explain a system | A08 Claude f42–121; B02 processing graph; B15 assembly | Stage actor/input → intermediary/connection → output/completion. A static camera may be enough. |
| Active-item importance can couple properties | B06 pill carousel; B07 action list | Coordinate position, size and width around a focal band; inactive objects remain context. |
| Full reveal can be earned through partial details | A03 Frameboy f0–334 | Show tactile close-ups before a full object; use depth/light to reveal actual geometry. |
| Camera travel should change conceptual scale | A03 diagram/output; B05 organization→worker→event; B16 task hierarchy | Specify the information revealed and the settled destination before choosing dolly, truck, zoom, arc or graphic scale. |
| Beauty framing and proof framing can differ | B16 oblique setup versus frontal code evidence | Use perspective selectively; settle and protect essential type/action when proof must read. |
| Flat composition does not imply a 3D camera | B10 frontal masks; A08 graph; B09 rotating globe | Separate object motion, scene translation, lens/framing scale and actual camera movement. Choose the simplest adequate representation. |
| A cut can preserve meaning without a literal morph | Memorable collection→graph; B07 chapter changes | Record transform, mask, matched replacement, hard cut or scene takeover accurately. Do not invent continuous geometry. |
| Stop motion is designed cadence, not asset instability | A15 TasteGraph; user interest in imagegen cutouts | Preserve identity/light/silhouette across poses; hold explicit output-frame counts and avoid unwanted interpolation/blur. |
| Constant intensity erases emphasis | B01 silhouette/lockup holds; B07 identity holds; Memorable sparse waiting state and outro | Plan density/energy contrast and readable destinations. A scene is not finished at peak velocity or overshoot. |

## Assets, sound, and finish

| Learning | Evidence / foundation | Skill decision |
|---|---|---|
| Dark objects need designed separation | B04 coin studies; B07 f801–1060 | Use curvature, thickness, grazing/rim light and roughness before adding bloom. |
| Asset generation belongs upstream of deterministic animation | User's cutout interest; authored production synthesis | Select versioned masters; keep exact type/logo/UI separate. Plan overscan and camera envelope before animation. |
| A still cannot reveal unseen surfaces | Physical-object observations and renderer research | Use geometry or coherent pre-renders when the shot requires new reflections, occlusion or surface exposure. |
| Finish is a treatment per layer | Clean UI, dark material, atmospheric fields, tactile cutouts across the collection | Choose grain, blur, glow, DOF and grade by the scene's purpose; keep important UI sharp and correctly colored. |
| Temporal blur differs from spatial blur | HyperFrames subframe accumulation source | Evaluate fractional time and exposure samples if selected. Measure its cost and inspect cuts/holds. |
| Sound must be designed with the edit | Pixar/story/edit research plus authored production synthesis | Plan voice/music/SFX/silence in the animatic, time a real read, and listen to the final mix. This source study did not listen to reference audio. |
| Sound can lead or outlast an image cut | Adobe split-edit guide | Use J/L cuts where they connect ideas or preserve continuity. Do not attach a whoosh to every movement. |
| Final encoded pixels are the deliverable | Color/render research and calibration | Check type, gradients, saturation, alpha/color path, compression and actual delivery variants after encoding. |

## Rendering and production process

| Learning | Evidence | Skill decision |
|---|---|---|
| GPU rendering, transfer and encoding are separate costs | HyperFrames Chrome/FFmpeg; FFrames Skia/wgpu/export source | Log actual negotiated paths and measure end-to-end time. Never call wgpu an instant encoder or universal fastest renderer. |
| Use existing backends before inventing a full engine | Source-pinned tool matrix and API recipe | Prototype the hardest actual shot in the candidate route, including fonts/media/effects/output, before moving the whole film. |
| Determinism is an authoring contract | Source renderer protocols and local repeat-seek check | Derive all tracks from absolute frame/time, seed variation, await readiness, and test reverse/random/fractional seeking. |
| Static analysis has a bounded scope | REA selected HyperFrames engine and FFrames editor analyses | Preserve commit, included/excluded files and unknowns. Rust source reading is not JavaScript static coverage; neither is a speed benchmark. |
| Role diversity needs one editorial owner | Team synthesis; bounded shot contracts | Art, UI, camera, motion, narration, composite and review share a premise, tokens, assets and clock. Assign file ownership and boundary states. |
| Every-frame thumbnails and final perception are different evidence | Actual source review coverage | Preserve all-frame index/sheets, add native-size detail and playback/audio review, and state exactly which passed. |
| Behavioral testing catches workflow mistakes | Isolated QueuePilot forward test | Test a realistic brief before release. Missing files, overcautious overlays, invented UI and unsupported speed claims are concrete defects to fix. |

## Implemented in this revision

The skill includes two direction guides, coordinated roles, story/duration/sound planning, a shot/asset/review contract, camera and deterministic GSAP guidance, finishing recipes, source-specific studies, renderer selection and native-wgpu integration research, an all-frame extraction helper, and a working inherited browser fallback. It is a portable instruction/evidence package, not model fine-tuning. Native-wgpu production rendering and comparative performance benchmarks have not been implemented or run here.
